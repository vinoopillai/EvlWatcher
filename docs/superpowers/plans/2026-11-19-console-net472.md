# EvlWatcherConsole on .NET Framework 4.7.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the WPF console from .NET 10 to .NET Framework 4.7.2 with its own flat light theme and vector icons, update the installer to check for .NET 4.7.2, and release as v3.1.0.

**Architecture:** The console stays an SDK-style project, now targeting `net472`, and keeps compiling the WCF contract from source. The Fluent theme is replaced by our own resource dictionary that defines brushes **under the same keys** the views already use, plus implicit styles with templates for every control in use. Icon font glyphs become `Geometry` resources drawn with `Path`.

**Tech Stack:** WPF on .NET Framework 4.7.2, C# 7.3, WCF (`System.ServiceModel`), MSTest 4 on net472, NSIS 3.

**Spec:** `docs/superpowers/specs/2026-11-19-console-net472-design.md`. Mockup B, which shows the target look: https://claude.ai/artifact/HQNSRsXSpLAaBCzS1TcUgs

## Global Constraints

- The console and the tests target `net472`, platform `AnyCPU`, and use C# 7.3: no file-scoped namespaces, no `init`, no records, no `ImplicitUsings`.
- No icon fonts: Segoe MDL2 Assets, Segoe Fluent Icons and `SymbolThemeFontFamily` must not appear anywhere. No Cascadia Mono. Monospace is `Consolas, Courier New`.
- Body text uses `Segoe UI`.
- The theme is light only. Every colour lives in a brush resource; views reference brushes and never use literal colours.
- Icon-only buttons keep their `ToolTip` and `AutomationProperties.Name`.
- `EvlWatcherModel.Call` keeps closing or aborting every channel. Nothing changes in the WCF contract or the service.
- New `.cs` files in the service projects must be added to the `.csproj` by hand. The console and the tests are SDK-style and glob their files.
- Version is 3.1.0. The 3.1.0 docs claim support for **Windows 8.1 / Server 2012 and later**, not Windows 7.
- The installer warns about a missing .NET 4.7.2 but **never blocks**; `/S` must run straight through.
- Build commands, run from `Source\`:
  - `dotnet build EvlWatcherConsole\EvlWatcherConsole.sln -c Release`
  - `dotnet test EvlWatcherConsole\EvlWatcherConsole.Tests -c Release`
  - `msbuild EvlWatcher\EvlWatcher.sln /p:Configuration=Release`, using Visual Studio's MSBuild

## Review Focus

1. **Disabled controls** (any button while the service is not responding) must look disabled: greyed text and greyed icon strokes. → Task 3's test checks that the icon stroke binds to the parent control's `Foreground`. Task 2's `Button` template needs an `IsEnabled=False` trigger, which the smoke test in Task 6 checks.
2. **Keyboard focus** on tabs, buttons, text boxes and lists must stay visible after templates are replaced. → Smoke test in Task 6: tab through every tab.
3. **A style key referenced by a view but missing from the theme** would crash at load time, outside any unit test. → Task 2's `ThemeResourceTests.EveryReferencedKeyExists`.
4. **High-DPI screens** (125% / 150%) must not blur or clip the window. → `app.manifest` sets system DPI awareness in Task 1; checked in Task 6.
5. **A missing .NET 4.7.2 on a silent install** must not stop the installer. → `/SD IDNO` on the message box in Task 4; Task 4 also runs the installer with `/S` against an install folder on the dev machine.
